# MedLingo｜中英医疗口译情境训练

**在模拟就医对话中，练习英译中、中译英和译员沟通判断。**

🎮 [进入游戏](https://maggiedu-u.github.io/medlingo/) · 💻 [源代码仓库](https://github.com/Maggiedu-u/medlingo)

本项目通过自然语言提出教学需求，使用大模型辅助编写和修改代码、设计病例对话与选项，并逐步根据实际使用反馈更新。游戏面向中英医疗口译学习者，可用于课堂演示、分组讨论和课后练习。

> 本说明对应截至 **2026-10-19** 已准备的最新合并更新：**全部场景开放、发热问诊7轮、访问次数统计**。线上实际功能取决于仓库是否已提交这些文件，以及 GitHub Pages 是否发布完成。

## 开始练习

1. 打开上方游戏链接，不需要学生注册 GitHub。
2. 在场景地图选择任意板块，先阅读本模块的中英词汇。
3. 进入场景，听完医护英文，再用中文口译。
4. 中文译文通过后，听完患者中文，再用英文口译。
5. 查看反馈并继续下一轮；遇到译员反应题，先选择合适的处理方式。

可用语音识别、键盘输入或选择表达完成任务。语音识别结果可编辑。正常播放时，需要等待说话人的完整话轮结束才能作答。

## 场景与功能

| 场景 | 主要练习内容 |
| --- | --- |
| 预约就诊 | 提出预约需求、确定时间、区分预约类型 |
| 到院登记 | 确认预约、拼写姓名、出生日期 |
| 发热与咽痛 | 症状与病程、药物过敏、治疗期望、工作顾虑和求助指示 |
| 急诊分诊 | 就诊原因、疼痛部位、疼痛评分 |
| 腹泻与脱水评估 | 腹泻次数、能否留住饮水、排尿变化 |
| 外伤 | 事故经过、伤处、承重与麻木、头部受伤及意识情况 |

- **所有场景自由进入**，不要求先完成前一关；已完成进度仍按实际通关记录。
- **双向口译**：医护英文 → 中文口译 → 患者中文 → 英文口译。
- **ASR（自动语音识别）**：将学习者说的话转换为文字，用于交互。
- **TTS（文本转语音）**：使用设备提供的音色朗读医护和患者台词，可在音色设置中试听和调整。
- **规则反馈**：按关键信息和部分同义表达检查回答，提供参考表达。
- **清晰操作栏**：底部显示当前任务及提交／继续按钮，主按钮采用绿色底白字。
- **场景图片**：不同场景配置对应人物与医院环境，图片为AI生成的虚构场景。

### 发热与咽痛：精简版

从12轮精简为 **7轮双向对话（14次口译）**，保留 **3道译员反应题**。

1. 症状、持续时间与最高体温。
2. 气短、皮疹和饮水困难筛查。
3. 药物过敏与本次抗生素使用情况。
4. 病毒感染判断与患者“怎么不开药、还要上班”的抱怨。
5. 打点滴期望与“消炎药”含义澄清。
6. 治疗建议、休息与患者工作顾虑。
7. 病情变化时的分级求助指示。

反应题关注：准确传达情绪与诉求、透明地请求术语澄清、完整转达紧急程度和求助方式。

## 手机、语音与进度

- 本项目实际使用反馈中，Chrome 可进行语音识别；Safari 曾出现启动后立即失败。具体支持仍取决于设备、浏览器版本、权限和网络，不能保证所有手机都可用。
- 尽量使用独立浏览器打开游戏；如果在微信等应用内无法识别，复制链接到浏览器再试。
- 允许网站使用麦克风。如果之前拒绝了，需要在浏览器的网站权限设置中重新允许，再刷新页面。
- 顶部“声音／麦克风检查”可用于排查。听不见声音时，也可在“音色设置”中查看设备可用音色。
- 当前使用浏览器提供的ASR，部分实现需要在线识别服务；TTS音色及自然程度也由设备决定。
- **通关进度保存在当前浏览器中**，不支持学生账号、跨设备同步或教师统一成绩后台。

- 每次打开或刷新页面发起一次计数请求，同一个人重复访问也累加。
- 游戏内切换关卡不重复计数，本地预览不计入正式网站统计。
- 接入后开始累计，无法补算接入前的访问；请统一分享上方末尾带 `/` 的游戏链接。

## 源码结构与修改位置

项目由 HTML、CSS、JavaScript 和图片构成，无需安装 npm 依赖或执行构建命令。

| 文件／目录 | 用途 |
| --- | --- |
| `index.html` | 游戏入口、页面框架、访问统计 |
| `css/` | 页面布局、动态效果及按钮样式 |
| `js/scenarios.js` | 六个基础场景的词汇和对话 |
| `js/fever-expanded.js` | 发热7轮对话、反应题及该病例检查规则 |
| `js/app.js` | 场景地图、通关记录、页面切换等基础逻辑 |
| `js/conversation.js` | 问答话轮基础逻辑 |
| `js/speech.js` | 双向口译流程、ASR/TTS及话轮等待 |
| `js/audio-repair.js` | 语音加载、设备检查与识别处理 |
| `js/assessment.js` | 其他场景的关键词与同义表达规则 |

**修改发热病例以 `js/fever-expanded.js` 为准**，该文件会覆盖基础场景中的发热数据。病例数据目前仍用 JavaScript 保存。脚本按顺序执行，暂勿随意改变加载顺序或改成异步加载。

## 发布与持续更新

本仓库通过 GitHub Pages 发布。入口 `index.html` 与 `css`、`js`、`assets` 应在仓库第一层。

1. 修改并检查相关文件。
2. 到仓库对应目录，选择 **Add file → Upload files** 上传同名更新文件，保持目录路径。
3. 将修改提交到 `main`；若使用其他分支，则先合并到 `main`。
4. 在 **Actions** 中确认本次 Pages 发布成功，再打开游戏刷新检查。
5. 在下方“更新日志”顶部记录本次修改内容和日期。

一次更新多个相关文件时，尽量一起提交。上传的是文件及目录内容，不是ZIP或多套一层的外部文件夹。网页网址不随一般内容更新而改变；已打开的页面需刷新才会加载新代码。

首次设置：**Settings → Pages → Deploy from a branch → main → /(root) → Save**。

每次发布后建议检查：场景能否进入、图片与按钮、医生先说完才开放作答、中英两个方向的识别、下一轮、反应题和通关反馈。访问统计需在正式网页上单独确认。

[GitHub：上传文件](https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository) · [GitHub：设置 Pages 发布源](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)

## 教学范围与限制

- 病例、人物和台词均为虚构教学材料，仍需临床及医疗口译专家审校，不作为诊断或用药指导。
- 游戏采用英国GP／急诊沟通情境参考。患者对英国医生的抱怨是个体角色台词，不代表对英国医疗服务的概括。
- 目前是固定病例、规则检查和分轮双向口译训练；不是自由生成的医患对话，也不是同时听说的完整同传模拟。
- 大模型用于辅助开发和内容制作；运行时的ASR、TTS及关键词判断，不等于大模型实时评价口译质量。
- 同义表达覆盖仍有限；自动通过／未通过不能替代教师对准确性、完整性和译员角色的评价。
- 图片及镜头效果不是真人视频或精确唇形同步。学生无需输入真实患者信息。
